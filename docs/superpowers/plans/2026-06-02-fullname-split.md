# Split `fullName` → `firstName` + `lastName` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single `fullName` column on `User` and `UserInvite` with first-class `firstName` + `lastName` fields, while keeping a *derived* `fullName` string on every API response so display sites are untouched.

**Architecture:** `firstName` + `lastName` become the DB source of truth (both required). The server stops selecting a physical `fullName` column; instead each query selects `firstName`/`lastName` and the API response layer projects `fullName: \`${firstName} ${lastName}\``. UI display sites keep reading `user.fullName` unchanged. Only *input* sites (create/invite/edit forms), the *greeting heuristic*, *search*, and *sort* change. better-auth's required `name` field is remapped from `fullName` → `firstName`.

**Tech Stack:** Expo React Native + Expo Router (Tamagui), Prisma (PostgreSQL), `prisma-zod-generator` → `@baza/types` Zod schemas, better-auth, Vitest (integration + unit), Resend/react-email.

**Key decisions (confirmed with user 2026-06-02):**
- Derived `fullName` for display; only input/sort/search/greeting sites change.
- `firstName` and `lastName` **both required** (`z.string().min(1).max(50)`), matching today's required `fullName` on admin-create/invite.
- Add `@@index([lastName])` and sort admin client lists by `lastName, firstName`.
- better-auth `name` field remapped to `firstName` (sign-up is disabled; the app creates users via its own `complete-invite` route, so better-auth only reads `name` incidentally).

**Critical sequencing note:** The schema migration + `prisma generate` (Task 1) **breaks the build everywhere** until the server layer is updated, because `packages/types/src/index.ts` `.pick({ fullName: true })` from regenerated Prisma-Zod schemas, and every `select: { fullName: true }` becomes a Prisma type error. So Tasks 1–2 (schema + types) and Task 3 (auth-guards + the shared name helper) must land together as one red→green arc before `tsc` is green again. Run `tsc --noEmit` only at the *end* of Task 5, not between every step inside Tasks 1–4 (it will be red mid-flight by design). Integration tests for each slice still gate each slice.

### The name helper (defined once in Task 2, used everywhere)

A single helper so derivation is DRY and consistent:

```ts
// packages/types/src/index.ts (add near the top, after the imports)
/** Display name derived from the normalized first/last fields. */
export function formatFullName(first: string, last: string): string {
  return `${first} ${last}`.trim();
}
```

Server projection sites import and call `formatFullName(u.firstName, u.lastName)`.
